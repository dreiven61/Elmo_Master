6.1.6 MMC_MoveAdditive
Commands a controlled motion of a specified relative distance additional to the most recent commanded
position in the discrete motion state.
MMC_LIB_API int MMC_MoveAdditiveCmd(
IN MMC_CONNECT_HNDL hConn,
IN MMC_AXIS_REF_HNDL hAxisRef,
IN MMC_MOVEADDITIVE_IN* pInParam,
OUT MMC_MOVEADDITIVE_OUT* pOutParam
);
Motion Mode NC - Supported Distributed - Supported
Source GMAS\includes\MMC_PLCopen_single_API.h
GMAS Programming(IEC 61331 Program)\ElmoSingleAxis
Parameters
hConn
[IN] Connection handle input using hConn, where MMC_CONNECT_HNDL is the
Connection Handle Type. It should be noted that this connection handle is c ommon
throughout all Maestro functions. This connection handle is returned by the Init
Connection command. If an error occurs, the function returns -1 and a MMC_LIB_API
error with more details.
hAxisRef
Axis/group reference handle type returned by the GetAxisRef command
pInParam
Points to the MMC_MOVEADDITIVE input data structure using the
MMC_MoveAdditive function.
pOutParam
Points to the MMC_MOVEADDITIVE_OUT output structure receiving information as a
result of calling the MMC_MoveAdditive function.
Remarks
The most recent commanded position may be the result of a previous MMC_MoveAdditive motion, which
was aborted. If the function block is activated in the Continuous Mode, the specified relative distance is
added to the actual position at the time of the execution.
Scope
MMC_MoveAdditive will only operate from Standstill, Continuous Motion, or Discrete Motion. It will not
operate from Stopping, Homing, ErrorStop, or Disabled. Refer to the State diagram in Figure 12.

The following figure shows two examples of the combination of two MoveVelocity function blocks:
35. 1. The left part of timing diagram illustrates the case if the Second function block is called after
the First one is completed. If First reaches the commanded velocity 3000 then the output
First.InVelocity AND the signal Next causes the Second function block to move to the velocity 2000. In
the next cycle First.InVelocity is Reset and First.commandAborted is SET. Therefore, the Execute of the
2nd function block is Reset. In addition, as soon as the axis reaches Velocity 2000 the
Second.InVelocity is set for 1 cycle (because the Second.Execute is set for only 1 cycle).
36. 2. The right part of the timing diagram illustrates the case if the Second move Function Block
starts the execution while the First function block is not yet InVelocity.
37. The following sequence is shown:
a. a. The First motion is started again by Go at the input First.Execute.
b. b. While the First function block is still accelerating to reach the velocity 3000 the First
function block will be interrupted and aborted because the Test signal starts the Run of the
Second function block.
c. c. Now the Second function block runs and decelerates the velocity to 2000.
