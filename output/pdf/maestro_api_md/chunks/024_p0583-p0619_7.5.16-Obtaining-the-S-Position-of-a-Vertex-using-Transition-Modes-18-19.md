###### 7.5.16 Obtaining the 'S' Position of a Vertex using Transition Modes 18 & 19
7.5.16 Obtaining the 'S' Position of a Vertex using Transition
Modes 18 & 19
In order to perform accurate 'Output Compare' where the output is set at a known position along a 2D / 3D
path, it is necessary to utilize a transition mode where the position can be defined by the user and the 2D / 3D
motion will by definition intersect through these points.
Two transitions are reformulated from previous similar transitions:
- Transition mode MC_TM_DIST_VEL_END_POINTS_MOVED_PLN6 = 18
This transition mode guarantees a transition smoothed by the velocity and acceleration, a nd can be
used for 2D and 3D transitions
- Transition mode MC_TM_DIST_VEL_END_POINTS_MOVED_PLN8 = 19
This transition mode guarantees a transition smoothed by the velocity, acceleration and jerk, and can
be used for 2D and 3D transitions. The only difference from the previous mode is continuity by jerk at
the connection points.
Only using one of the above transitions promises intersecting a precise pos ition. In order to evaluate where this
position is along the path - 'S' ('Position along the path') - the length of the line to the vertex must be
extracted.
7.5.16.1 Scope
The purpose of this document is to describe how to obtain the 'S' Position of a Vertex usi ng two dedicated
Transition Modes. This document discusses how to extract the length of the line to the vertex for numerous
FB's in the queue.
7.5.16.2 Obtaining Motion Segment Information
7.5.16.2.1 General
The 'S' parameter is a rising monotonous value representing the posi tion along a path. This parameter is a
double precision parameter that can be reset by the user by writing to the MCS_S_DIRECTION parameter.
The following information can be obtained from the motion segments:
- Distance along the transition curve from its start point to the vertex
- Length of the transition curve
- Length of the line
This data is returned to the user using the function GetMotionInfo, prior to performing the motion.

<a id="pdf-page-584"></a>
7.5.16.2.2 Working Method
The following pseudo code should be called:
1. Reset MCS_S_DIRECTION.
2. Insert WaitForEvent into group motion queue
3. Insert blended segments, while last segment ONLY is with Execute b it = 1.
In Transition[15] , enter any relevant user data as recognition when operating the function
GetMotionInfo.
4. Call the function GetMotionInfo(TRANSITION_INFO)
5. Set Output Compare Information according to data obtained from the function GetMotionInfo
6. Set the parameter MMC_TriggerMotion which will trigger the condition to run the event. The motion
and Output Compare operation is started.
7.5.16.2.3 New Function - GetMotionInfo
The new function returns an array of structures - where each structure returns the following information:
- FB index given by user. This is returned internally by new pFbCommon ->dbUserData parameter
- Distance along the transition curve from its start point to the vertex
- Length of the transition curve
- Length of the line
- Spare[XXX] parameter for later use
- User data inserted when setting Transitions [15] and [16] is returned
The input to the function is the motion data to be returned (In our case this is TRANSITION_INFO) - so in the
future - additional data may be returned.
This function can be used in the languages C, C++, and Dot Net:
- C API - Using an enumeration to define which data is to be returned. A differe nt structure using a
Union can be returned as requested.
- CPP / .NET API - Uses a dedicated function per type. Currently should work in the G roupMotion class
only, but can easily used for a Single axis.
7.5.16.2.4 New Parameter - MMC_TriggerMotion
This Boolean axis related parameter (Single and Group) receives (from the user) a value of "1" only to trigger
the condition to run the event. This parameter invokes and releases the Motion queue waiting on this
parameter. The motion queue, once released, automatically resets this parameter to 0.

###### 7.6.1 Border mode

CircMode = BORDER
Defines the end point (dEndPoint) and a border

###### 7.6.2 Center mode
7.6.2 Center mode

CircMode = CENTER
Defines the endpoint and the center point
(dCenterPoint) of the circle (equivalent to the
AuxPoint in the PLCopen standard). When
using this mode, the input PathChoice defines
whether the Short or the Long sector is
travelled by the machine.
This parameter is restricted to angles < 2π and
!= π in one single command.

###### 7.6.3 Radius mode
7.6.3 Radius mode

CircMode = RADIUS
Defines the end point and the perpendicular
vector of the circle plane. The length of the
vector corresponds to the radius of the circle.
The spearhead point of the vector is the input
signal dSpearHeadPoint in absolute
coordinates (equivalent to the AuxPoint in the
PLCopen standard), i.e. referring to the origin
of the coordinate system specified in
CoordSystem.
If the diameter is larger than the distance
between starting and end point, two different
circles have to be considered. When using this
mode, the user defines a choice of Pathchoice;
clockwise or counterclockwise, and
ArcShortLong; Short or Long segment.
Clockwise or counterclockwise direction is
defined as seen from the end of the
perpendicular vector described by the user.
This parameter is restricted to angles < 2π in
one single command and the perpendicular
vector has to be computed.
Example:
dSpearHeadPoint = (50,0,0) -> Circle in plane
parallel to yz plane with radius 50 and rotation
around axis parallel to x-axis (CoordSystem =
MCS).

###### 7.6.4 Angle Mode
7.6.4 Angle Mode
The angle is the relative angular position for the coordinate system specified by the input signal CoordSystem,
measured in degrees. The functions MMC_MoveCircularAbsoluteAngle and
MMC_MoveCircularAbsoluteAngleEx are appropriately defined to provide circular motion for the relative
angular position mode.
Alternatively, the function MMC_MoveAngle allows a user to specify a certain plane for the arc motion. It uses
the original MMC_MoveCircularAbsoluteAngle but with consideration to the s elected plane. In this case, the
arc motion will only be performed in one of the planes perpendicular to each other in space (XY, XZ , or YZ).
[PDF field-code object omitted]
The angles range may be any positive or negative number (e.g. 1012 is quite acceptable). In principle, an angle
larger than 360 deg, means multiple rotations of an object in the direction defined.

##### 7.7 Multiple Axes Motion Control - Normalcy Modes
7.7 Multiple Axes Motion Control - Normalcy Modes
Normalcy in multiaxes operations is described as motion normal or normal tangential to the plane of motion. A
practical example of the use of Normalcy is with cutting tools that must be perpendicular (normal) to the part
being cut. Such tools typically mount to a rotational axis so that the orientation of the tool can be changed as
the position of the part changes. Normalcy motion is generated from the commanded position (not feedback)
of the normalcy axes. Figure 185 shows a robot rigged to cut at normalcy to the part.

Figure 185: Cutting Robot Rigged to Cut at Normalcy to Part
In the normalcy mode, the controller automatically maintains the relationship between the cutting tool axis
and the axes that compound the normalcy plane.

##### 7.8 Multiple Axes Motion Control - Splines
7.8 Multiple Axes Motion Control - Splines
Splines can be defined for the motion of a vector/system, designed where all the potential trajectory points are
known in advance. The user is interested in the smoothest trajectory obtainable. Therefore using Splines may
be the solution.
Splines are defined as n dimensional position points (1 < n<=16), which describe the geometry of the traject ory.
The kinematics of the trajectory can be defined in two ways:
a) By the time interval between each point
b) By the kinematic parameters: Max Velocity, Max Acceleration, Max Deceleration, and Jerk.
Either way, the spline is designed as a sequence of cubic polynomials continuous by the first and second
derivatives. The following Spline modes define kinematic options:
Spline mode Explanation
MC_SPLINE_MODE_FT = 1 In modes MC_SPLINE_MODE_FT and
MC_SPLINE_MODE_V_AC_DC the Spline Velocity is a parabolic
function of time.
MC_SPLINE_MODE_V_AC_DC = 2
MC_SPLINE_MODE_CV = 7 In modes MC_SPLINE_MODE_CV and MC_SPLINE_MODE_NP the
Spline is executed with Constant Velocity with an Acceleration
segment at the start and Deceleration segment at the end.
MC_SPLINE_MODE_NP = 3
MC_ONLINE_SPLINE_MODE_CV = 9
When would a user prefer one mode to another?
If the user requires a minimal time for the whole trajectory but constant velocity is not required, the Spline
mode V_AC_DC should be selected.
If on the other hand, the user knows the precise time intervals between each two points and a constant
velocity is not required, the Spline mode FT should be selected.
If the trajectory must be executed with constant velocity, then the user should select the Spline modes CV or
NP.
Having selected the appropriate Spline mode, a Spline data table (or series of Spline tables) is created (in Excel
or otherwise) according to the definitions and explanations described in the next sub- sections. This Spline table
is saved as a text file, and downloaded to the Maestro. Its possible file path may then be, for example:
/mnt/jffs/usr/Spline_2D.txt

###### 7.8.1 Spline Mode MC_SPLINE_MODE_FT = 1
7.8.1 Spline Mode MC_SPLINE_MODE_FT = 1
In spline mode FT the user defines the spline mode, dimension (number of axes 1 -16), number of points N and
a table of points. Each row of the table has the same structure and contains information for the point i. The
first column of the row i contains dTi, the time interval (in seconds) required to arrive at point i from point i -1.
The next row contains the position coordinates for the point i.

Spline in mode FT comprises of a function of time in continuous velocity and acceleration. Each segment i is a
cubic polynomial of time with parameter deviation dT
i. This polynomial is built for each coordinate j. Velocities
and accelerations are predefined by the parameters dTi, i = 1,2,....N, but are limited by the parameters

undesirable deviations from the original polygon, some position control is implemented for the short
splines (N < 50). This is performed by inserting additional internal points. If t he user is dissatisfied with some
interval on the spline curve, he can manually add a number of internal points.
Spline mode MC_SPLINE_MODE_FT should be used if the user can define precise time intervals for each
segment and is not interested in constant velocity along the spline.

The difference with the mode CV is in definition of the parameter "S", whereas the NP modes is close to the
natural parameter. In reality, for short splines (N < 50) and smoothed curves, the parameter is completely
natural. The advantage of the natural parameter is that the resultant spline does not require any additional
calculations in real-time. On the other hand, to build such a spline without using the natural parameter can
employ considerable off-line calculations (a couple of minutes for the long and unsmoothed spline). Smoothed
splines like ellipse and helix do not need long iterative calculations.

stage, and deceleration.

points.

spline curve. This constant velocity is limited by the user defined V
max and
Vρ = [MMC_MAX_ACCELERATION_PARAM *ρmin]1/2
where ρmin is the minimal radius of curvature on the spline curve.
So Vconst = min(Vmax, Vρ) .
This limitation usually does not influence smoothed trajectories like ellipse or helixes. This mode is
recommended in situations where there are problems with the CV mode.
