# SIGMATEK LASAL 프로그래밍 방법 스터디

작성일: 2026-06-17

이 문서는 `Elmo_EtherCAT_Test_4Axis` LASAL 프로젝트를 수정할 때 필요한 구조와 작업 방법을 정리한 문서다. 기준 자료는 현재 소스, `docs/PMAS_LASAL_Integrated_Analysis_2026-04-10.md`, `Codex_LASAL_WPF/API_MAPPING.md`, `Codex_PMAS_WPF/API_MAPPING.md`다.

## 1. 현재 프로젝트 구조

- LASAL 프로젝트 루트: `Elmo_EtherCAT_Test_4Axis/`
- 주요 영역:
  - `Class/`: LASAL class 정의와 구현
  - `Include/`: CodeGenerator가 만든 channel/type/header
  - `Network/`: HW/Motion network 구성
  - `ProjectInternal/`: IDE 내부 상태
  - `Source/`: C/C++ interface/header 자료
- WPF 연동:
  - PMAS 원본 기준: `Codex_PMAS_WPF/`
  - SIGMATEK TCP/IP 이식 기준: `Codex_LASAL_WPF/`

## 2. LASAL 파일 성격

- `.st`: 사람이 읽고 검토 가능한 LASAL Structured Text/클래스 export다.
- `.lcb`, `.lcp`, `.lcn`: 프로젝트/클래스/네트워크 등록 정보 성격이 강하고 바이너리 diff로 판단하기 어렵다.
- `.lba`, `.lob`, `.ldi`, `.lhd`: LASAL IDE/빌드 생성물 성격이 강하다.
- `ProjectInternal/`: IDE 내부 상태다. 설계 근거가 아니다.

정확한 결론: 새로 생성되는 `.lba/.lob/.ldi/ProjectInternal`은 추적하지 않는 쪽이 맞다. 단, 이미 Git에 tracked인 파일은 `.gitignore`로 사라지지 않는다.

## 3. CodeGenerator 영역

작업 기준:

- 직접 수정해야 할 경우 `//{{LSL_IMPLEMENTATION` 이하 사용자 구현 영역과 생성 영역을 구분한다.
- 채널 추가 시 XML, class member, `@CT_`, `@STD`가 서로 맞는지 확인한다.

## 4. TCP/IP 구현 방법

WPF에서 LASAL로 명령을 보내는 흐름은 다음 기준으로 본다.

1. C# WPF가 TCP frame 생성
2. LASAL TCP server/interface가 frame 수신
3. Parser가 command id, target, payload를 검증
4. 주기 함수가 command queue를 실행
5. 결과 frame을 C#으로 응답

주의:

- TCP callback에서 받은 포인터를 보관하지 않는다.
- 수신 callback에서 긴 motion wait를 수행하지 않는다.
- command id와 payload offset은 C#과 LASAL 문서가 같은 값을 가져야 한다.

## 5. 현재 확인된 PMAS/LASAL 매핑 기준

현재 분석 문서 기준으로 확인한 프레임/기능은 아래처럼 다룬다.

- `MoveAbsoluteEx` 계열: `0x209F` 관측
- `ReadActualPosition` request: `0x202E` 관측
- `ReadActualPosition` response: 기존 LASAL 구현에서 `0x00E0` 사용 이력 존재
- Group Motion/GroupReadStatus는 PMAS WPF에서 테스트 중이며, LASAL 구현은 실제 group/robot class 연결이 확인된 뒤 확정한다.

이 값들은 현재 문서/코드에서 확인한 사실이다. Elmo 원본 API와 SIGMATEK 구현이 1:1로 같다고 단정하지 않는다.

## 6. Axis/Network 작업 방법

- `Elmo_11`과 `PosController1/_LMCAxis1` 연결을 기준점으로 사용한다.
- `Elmo_2`, `Elmo_3`, `Elmo_4` 추가 시 아래 항목을 같은 패턴으로 맞춘다:
  - drive object
  - axis object
  - Client/Server channel
  - Motion network 연결
  - include/channel generated header
- 네트워크 변경 후에는 `Motion_Network.lcn`, `Networks.lcb`, `ONE_Motion_Network_Table.st`를 같이 확인한다.

## 7. ST 문법 주의점

- `CASE ... OF` 기본 분기는 `else`를 사용한다.
- 기존 프로젝트에서 검증된 OR 표현은 `|`다.
- 외부 Client 호출 전 연결 여부를 확인한다.
- 축 명령 함수는 blocking 구조로 만들지 않는다.
- 상태 bit와 error code는 숫자만 남기지 말고 의미를 문서에 남긴다.

## 8. Group Motion 설계 방향

Group Motion을 붙일 때는 아래 순서로 진행한다.

1. SIGMATEK group/robot motion class가 실제 프로젝트에 포함되어 있는지 확인한다.
2. group object와 axis member 연결을 LASAL Network에서 확정한다.
3. `MoveLinearAbsolute`, `MoveLinearAbsoluteEx`, `GroupReadStatus`에 해당하는 API entry를 분리한다.
4. Transition Mode와 blending 조건은 normal move와 queue/blend move를 분리해서 테스트한다.
5. WPF의 `Cycle Test Group1` 로그와 LASAL 응답 frame을 같은 cycle id로 매칭한다.

Group 구현이 확정되지 않은 상태에서 Elmo API 이름만 맞춘 더미 성공 응답을 만들면 안 된다.

## 10. 결론

LASAL 작업은 일반 C# 코드처럼 텍스트 diff만으로 판단하면 안 된다. 사람이 수정하는 `.st/.h/.cpp/.c`와 IDE/빌드 생성물을 분리하고, TCP frame과 Network 연결은 WPF 코드, LASAL 코드, 문서를 함께 맞춰야 한다.
