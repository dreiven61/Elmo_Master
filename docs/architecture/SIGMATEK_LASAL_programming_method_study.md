## 1. 현재 프로젝트 구조

- LASAL 프로젝트 루트: `Lasal_PRG/Elmo_EtherCAT_Test_4Axis/`
- 주요 영역:
  - `Class/`: LASAL class 정의와 구현
  - `Include/`: CodeGenerator가 만든 channel/type/header
  - `Network/`: HW/Motion network 구성
  - `ProjectInternal/`: IDE 내부 상태
  - `Source/`: C/C++ interface/header 자료
- WPF 연동:
  - PMAS 원본 기준: `Codex_PMAS_WPF/`
  - SIGMATEK legacy/dummy 참고: `Codex_LASAL_WPF/`
  - canonical LASAL-DINT API 계약: `LMC_Library/LMC_API_Delivery/src/`와 tests

## 2. LASAL 파일 성격

- `.st`: 사람이 읽고 검토 가능한 LASAL Structured Text/클래스 export다.
- `.lcb`, `.lcp`, `.lcn`: 프로젝트/클래스/네트워크 등록 정보 성격이 강하고 바이너리 diff로 판단하기 어렵다.
- `.lba`, `.lob`, `.ldi`, `.lhd`: LASAL IDE/빌드 생성물 성격이 강하다.
- `ProjectInternal/`: IDE 내부 상태다. 설계 근거가 아니다.

정확한 결론: 새로 생성되는 `.lba/.lob/.ldi/ProjectInternal`은 추적하지 않는 쪽이 맞다. 단, 이미 Git에 tracked인 파일은 `.gitignore`로 사라지지 않는다.

## 3. CodeGenerator 영역

LASAL `.st` 파일 상단에 아래 문구가 있으면 IDE가 다시 생성할 수 있다.

```text
Please, do not edit this file
```

작업 기준:

- 선언/채널/테이블 영역은 IDE 재생성 대상일 수 있다.
- 직접 수정해야 할 경우 `//{{LSL_IMPLEMENTATION` 이하 사용자 구현 영역과 생성 영역을 구분한다.
- 채널 추가 시 XML, class member, `@CT_`, `@STD`가 서로 맞는지 확인한다.
- 새 custom source의 선언/구현과 IDE metadata 이름/comment는 7-bit ASCII로
  입력하고 한국어 설명은 Markdown 문서에 남긴다.
- 기존 vendor/library source는 인코딩이나 줄바꿈을 일괄 변환하지 않는다.

## 4. TCP/IP 목표 구현 방법

WPF에서 LASAL로 명령을 보내는 목표 흐름은 다음과 같다.

1. C# WPF가 TCP frame 생성
2. LASAL TCP server/interface가 frame 수신
3. Parser가 command id, target, payload를 검증
4. 주기 함수가 command queue를 실행
5. 결과 frame을 C#으로 응답

현재 tracked source는 `Response()`가 frame을 depth-8 queue에 게시하고,
non-RT `CyWork()`가 승인 명령을 실행·응답하는 구조다. interface RT task,
`RtWork()` override, RT mailbox와 atomic state는 사용하지 않는다. 지원하지 않는
명령은 deterministic error `-5`로 응답한다. LASAL IDE Rebuild와 PLC 동작 시험
전에는 source 구현 상태로만 판정하며 상세 gate는 오류 예방 지침서와
`LMC_Library/LMC_API_Delivery/docs/LASAL_CYWORK_ONLY_TCP_EXECUTION_DESIGN_2026-07-13.md`를
따른다.

주의:

- TCP callback에서 받은 포인터를 보관하지 않는다.
- 수신 callback에서 긴 motion wait를 수행하지 않는다.
- command id와 payload offset은 C#과 LASAL 문서가 같은 값을 가져야 한다.

## 5. 현재 확인된 PMAS/LASAL 매핑 기준

현재 tracked source의 CyWork 실행 상태는 아래처럼 구분한다.

| 상태 | command id와 기능 |
|---|---|
| 승인 | `0x2023 Power`, `0x2024 Reset`, `0x2022 Stop`, `0x2028 ReadStatus`, `0x202E ReadPosition` |
| 승인 | `0x209F MoveAbsolute`, `0x20A0 MoveRelative`, `0x20A2 MoveVelocity` |
| 승인, LASAL local extension | `0x204A GroupPowerOn`, `0x204B GroupPowerOff` |
| 승인 | `0x2047 GroupEnable/ProfileLock`, `0x2048 GroupDisable/ProfileUnlock`, `0x2045 GroupReadStatus` |
| 승인, 정적 4축 제한 | `0x2049 GroupReset`, `0x2085 GroupStop`, `0x20A4 MoveLinear` |
| 승인, 정적 identity 제한 | `0x2051 GroupReadActualPosition`, `0x20E7 SetKinTransform` |

이 표의 승인은 source handler 실행 경로 기준이다. LASAL IDE Rebuild와 PLC 동작
시험은 아직 완료되지 않았으므로 production 완료를 뜻하지 않는다.
`0x204A/0x204B`는 기존 23개 캡처 명령이 아닌 project-local extension이며 ACK는
비동기 `RobotOn`/`RobotOff` 요청 접수만 뜻한다. 정상 group 순서는
`PowerOn -> IsPowerOn(0x00040000) 확인 -> SetKin(static mapping only) ->
Enable/LockProfile -> motion -> Disable/UnlockProfile -> PowerOff ->
IsPowerOn=false 확인`이다.
`GroupReadStatus`의 `0x00040000`만 local Power Ready 확장이다.
`0x00020000=NC_GROUP_STANDBY_MASK`와 `0x00010000=NC_GROUP_DISABLED_MASK`는
Maestro 표준이며, 현재 어댑터가 각각 locked standby(`IsStandby/IsEnabled`)와
unlocked disabled(`IsDisabled`) 조건에 mapping한다.
`GroupReset`은 `AxQuitError(AxisNo:=0)` 기반 axis/hardware error reset이며 robot
profile error 전체 초기화가 아니다. `GroupStop` ACK도 정지 완료가 아니라 command
접수이므로 두 명령 모두 `GroupReadStatus`로 후속 상태를 확인한다.

이 값들은 현재 문서/코드에서 확인한 사실이다. Elmo 원본 API와 SIGMATEK 구현이 1:1로 같다고 단정하지 않는다.

## 6. Axis/Network 작업 방법

- `Elmo_11`과 `PosController1/_LMCAxis1` 연결을 기준점으로 사용한다.
- `Elmo_2`, `Elmo_3`, `Elmo_4` 추가 시 아래 항목을 같은 패턴으로 맞춘다:
  - drive object
  - axis object
  - Client/Server channel
  - Motion network 연결
  - include/channel generated header
- 네트워크 변경 후에는 `Motion_Network.lcn`, `Networks.lcb`, `ONE_Motion_Network_Table.st`를 같이 확인한다.

## 7. ST 문법 주의점

- `CASE ... OF` 기본 분기는 `else`를 사용한다.
- 기존 프로젝트에서 검증된 OR 표현은 `|`다.
- 외부 Client 호출 전 연결 여부를 확인한다.
- 축 명령 함수는 blocking 구조로 만들지 않는다.
- 상태 bit와 error code는 숫자만 남기지 말고 의미를 문서에 남긴다.

## 8. Group Motion 설계 방향

Group Motion을 붙일 때는 아래 순서로 진행한다.

1. SIGMATEK group/robot motion class가 실제 프로젝트에 포함되어 있는지 확인한다.
2. group object와 axis member 연결을 LASAL Network에서 확정한다.
3. `MoveLinearAbsolute`, `MoveLinearAbsoluteEx`, `GroupReadStatus`에 해당하는 API entry를 분리한다.
4. Transition Mode와 blending 조건은 normal move와 queue/blend move를 분리해서 테스트한다.
5. WPF의 `Cycle Test Group1` 로그와 LASAL 응답 frame을 같은 cycle id로 매칭한다.

Group 구현이 확정되지 않은 상태에서 Elmo API 이름만 맞춘 더미 성공 응답을 만들면 안 된다.

## 10. 결론

LASAL 작업은 일반 C# 코드처럼 텍스트 diff만으로 판단하면 안 된다. 사람이 수정하는 `.st/.h/.cpp/.c`와 IDE/빌드 생성물을 분리하고, TCP frame과 Network 연결은 WPF 코드, LASAL 코드, 문서를 함께 맞춰야 한다.
