# SIGMATEK LASAL 코딩 규칙

작성일: 2026-06-17

최종 갱신: 2026-07-13

이 문서는 `Lasal_PRG/Elmo_EtherCAT_Test_4Axis`에서 LASAL 코드를 수정할 때
매번 확인할 실무 규칙이다. IDE 장애 예방과 복구 절차는
[`SIGMATEK_LASAL_programming_error_prevention_guide.md`](SIGMATEK_LASAL_programming_error_prevention_guide.md)를
필수로 함께 따른다.

## 1. Git 추적 기준

- 추적 대상:
  - 사람이 읽고 수정하는 LASAL 소스: `Class/**/*.st`, `Class/**/*.h`, `Class/**/*.cpp`, `Class/**/*.c`
  - 프로젝트 등록과 네트워크 구성 판단에 필요한 파일: `*.lcp`, 선택된 `*.lcn`, `ONE_*_Table.st`, `Include/**/*.h`
  - 문서: `docs/**/*.md`
- 무시 대상:
  - LASAL 빌드/IDE 생성물: `*.lba`, `*.lob`, `*.ldi`, `*.lhd`, `*.lcc`, `*.o`, `*.bin`
  - IDE 내부 상태: `ProjectInternal/`
  - 실험 결과/캡처: `Reports/`, `*.pcapng`, `downloads/`
  - 임시 파일: `*.log`, `*.lst`, `*.map`, `*.err`, `*.tmp`, `*.bak`, `*.lock`
- 이미 Git에 추적된 파일은 `.gitignore`로 숨겨지지 않는다. `*.lba`, `*.lcb`, `*.lcp`, `*.lcn`이 status에 보이면 먼저 `git ls-files <file>`로 tracked 여부를 확인한다.
- `.lcb`, `.lcp`, `.lcn`, `.lba` 같은 LASAL 파일은 diff만 보고 의미를 판단하지 않는다. LASAL IDE 변경 결과로 필요한지, 단순 IDE 상태 변경인지 분리해서 커밋한다.

## 2. 수정 전 확인 순서

1. 변경 대상이 `Class`, `Network`, `Include`, `Source`, `ProjectInternal` 중 어디인지 분리한다.
2. 작업 대상이 Git 추적 기준 프로젝트인지 확인하고 `_Edit` 복제본과 혼동하지 않는다.
3. `ProjectInternal/`은 설계 근거로 쓰지 않고 직접 수정하지 않는다.
4. `.st` 파일 상단에 `Please, do not edit this file`가 있으면 생성 영역과 사용자 구현 영역을 구분한다.
5. XML `<Channels>`, 클래스 멤버, `@CT_`, `@STD`, 구현부가 같은 구조인지 확인한다.
6. TCP 프레임, command id, endian, payload offset, 축 단위가 바뀌면 C# 송신 코드와 문서를 같이 고친다.
7. 새로 작성하는 LASAL custom source의 선언/구현, 식별자, 주석, 문자열과 IDE에
   입력하는 class/object/channel/network 이름 및 comment는 7-bit ASCII만 사용한다.

## 3. Class 작성 규칙

- 통신, 파서, 큐, 축 제어, 응답 생성을 한 클래스에 계속 몰아넣지 않는다.
- 권장 분리:
  - TCP facade: 외부 수신, command queue, dispatch
  - Parser: command id, payload length, endian, target 검증
  - Robot/Axis adapter: `_LMCAxis`, group/robot motion 호출
  - `_TCPIPServerInterface` 계층: TCP server lifecycle와 socket callback
- 외부 객체 의존성은 `Client` 채널로 받는다.
- 채널을 추가/삭제하면 아래를 한 세트로 맞춘다:
  - XML `<Channels>`
  - `ClassName : CLASS`의 `Server`/`Client` 멤버
  - `@CT_` server/client count와 항목
  - `@STD` 초기값과 내부 네트워크 항목

## 4. ST 문법/구현 규칙

- `CASE ... OF` 기본 분기는 `default:`가 아니라 `else`를 사용한다.
- 이 프로젝트에서 검증된 OR 표현은 `|`다. `OR`는 기존 코드/컴파일 근거 없이 새로 쓰지 않는다.
- 새 custom source 또는 IDE metadata에 한글, 이모지, 스마트 따옴표, 전각 문자를 넣지 않는다. 한국어 설명은 `docs/**/*.md`에 기록한다.
- 기존 vendor/library 소스의 확장 문자를 일괄 변환하거나 파일 전체를 재인코딩하지 않는다.
- BOM과 줄바꿈을 의미 없이 바꾸지 않는다.
- TCP callback에서 받은 `pData` 포인터를 함수 종료 뒤 보관하지 않는다.
- 모션 함수 안에서 장시간 blocking wait를 만들지 않는다. 수신, 큐잉, 실행, 응답을 분리한다.
- command id, status bit, payload offset, endian은 상수화하거나 문서에 남긴다.

## 5. TCP/IP 프로토콜 규칙

- `Response(pData, udSize, dSock)`에서는 아래까지만 수행한다:
  - frame length 검증
  - command id/target/payload 파싱
  - 즉시 가능한 error response
  - 실행 큐 적재
- 실제 축 명령은 승인된 주기 함수에서 큐를 하나씩 꺼내 실행한다.
- 현재 tracked `TCPMotionInterface`는 `Response()`가 frame을 depth-8 queue에
  복사하고 `CyWork()`가 분류·실행·응답하는 non-RT 구조다. interface의 RT
  task, `RtWork()` override, typed RT mailbox와 atomic state는 사용하지 않는다.
- 현재 CyWork handler가 승인된 명령은 `0x2023 Power`, `0x2024 Reset`,
  `0x2022 Stop`, `0x2028 ReadStatus`, `0x202E ReadPosition`,
  `0x209F MoveAbsolute`, `0x20A0 MoveRelative`, `0x20A2 MoveVelocity`,
  `0x2047 GroupEnable`, `0x2048 GroupDisable`, `0x2045 GroupReadStatus`다.
- `0x2049 GroupReset`, `0x2085 GroupStop`, `0x20A4 MoveLinear`,
  `0x2051 GroupReadActualPosition`, `0x20E7 SetKinTransform`은 지원하지 않으며
  deterministic error `-5`를 반환한다. 기존 helper body 존재 여부와 runtime
  지원 여부를 혼동하지 않는다.
- source 기준 handler 승인은 완료됐지만 LASAL IDE Rebuild와 PLC 동작 시험은
  남아 있다. 이 검증 전에는 production 완료로 승인하지 않는다.
- 일반 `_TCPIPServer1`과 interface는 같은 cyclic task에 두고, client method를
  호출하는 CyWork는 axis RT thread와 같은 core에서 같거나 낮은 priority로
  배치한다.
- canonical C# wire 계약은 `LMC_Library/LMC_API_Delivery/src`와 해당 golden/parser
  test를 기준으로 PLC parser와 바이트 단위로 맞춘다.
- `Codex_LASAL_WPF/PmasApiWpfTestApp/Services/SigmatekTcpIpDummyMMCLib.cs`도 변경마다
  대조하되, legacy PMAS/hybrid frame 또는 local-only dummy 동작이 남아 있으면
  불일치를 문서화하고 canonical E2E client로 사용하지 않는다. 현재 dummy의
  `ReadStatus()`는 TCP `0x2028`을 전송하지 않는다.
- `MoveAbsoluteEx`, `ReadActualPosition`, `ReadStatus`, `GroupReadStatus`는 요청/응답 command id와 payload 길이를 문서에 남긴다.

## 6. Motion/Axis 규칙

- API 계층은 EtherCAT PDO나 DS402 register를 직접 만지지 않는다. `_LMCAxis`, `ECAT_DS402Base`, 기존 drive class를 통해 접근한다.
- Axis Client는 연결 여부를 확인한 뒤 호출한다.
- 승인 목록 밖의 Group Motion은 실제 SIGMATEK group/CNC 구현 클래스와 의미가
  확정되기 전까지 deterministic error `-5`로 막는다.
- `Elmo_1` 기준으로 복제한 `Elmo_2`, `Elmo_3`, `Elmo_4`는 채널/네트워크 연결을 서로 대조한다.

## 7. Network 규칙

- `Motion_Network`에서 객체 연결을 바꾸면 `ONE_Motion_Network_Table.st`, `Motion_Network.lcn`, `Networks.lcb` 변경을 같이 확인한다.
- `Elmo_11`과 `PosController1/_LMCAxis1` 연결을 기준점으로 삼고, 추가 축은 같은 패턴으로 맞춘다.
- 네트워크 파일은 바이너리/생성 성격이 있으므로 텍스트 diff만 보고 판단하지 않는다.

## 8. 정적 확인 명령

```powershell
$root = 'Lasal_PRG/Elmo_EtherCAT_Test_4Axis'

rg -n 'default:|GUID=.NULL|Client Name="_StdLib"|CltChCmd__StdLib' Lasal_PRG\Elmo_EtherCAT_Test_4Axis\Class
rg -n 'ReadActualPosition|MoveAbsolute|MoveLinear|GroupReadStatus|0x202E|0x209F' Codex_LASAL_WPF Lasal_PRG\Elmo_EtherCAT_Test_4Axis docs
git status --short -- $root
git diff HEAD --unified=0 -- $root |
  Select-String -Pattern '^\+(?!\+\+\+).*[^\x00-\x7F]'
git ls-files --others --exclude-standard -- $root |
  Where-Object { $_ -match '\.(st|h|c|cpp)$' } |
  ForEach-Object { Select-String -LiteralPath $_ -Pattern '[^\x00-\x7F]' }
git diff --check
git diff --cached --check
```

비ASCII 검사에 `rg`를 사용하면 invalid UTF-8 또는 legacy single-byte high byte를
놓칠 수 있으므로 위 검사는 PowerShell `Select-String`을 사용한다.

## 9. 문서 동기화

- TCP 프레임이 바뀌면 `docs/PMAS_LASAL_Integrated_Analysis_2026-04-10.md` 또는 별도 분석 문서를 갱신한다.
- WPF API 매핑이 바뀌면 `Codex_PMAS_WPF/API_MAPPING.md`, `Codex_LASAL_WPF/API_MAPPING.md`를 확인한다.
- 패킷 분석 결과는 `packet_capture/` 아래 별도 md로 남긴다.

## 10. 커밋 전 체크리스트

- `.lba/.lob/.ldi/.lhd/.bin/ProjectInternal` 신규 파일이 의도 없이 staged 되지 않았다.
- 이미 tracked인 LASAL 생성 파일 변경은 왜 필요한지 커밋 메시지나 문서에서 설명 가능하다.
- C# 송신 프레임과 LASAL 파서가 같은 command id, endian, payload offset을 사용한다.
- 새로 추가한 LASAL custom source와 IDE metadata 입력에 비ASCII 문자가 없다.
- 변경 클래스의 `Find in Implementation` smoke test가 성공하고 smoke 시작 이후 `Lasal2.log`에 새 `CInvalidArgException`이 없다.
- `git diff --check`와 `git diff --cached --check`를 통과한다.
