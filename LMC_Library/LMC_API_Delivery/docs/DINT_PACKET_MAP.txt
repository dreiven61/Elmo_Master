LMC DINT packet map

request/public/handler paths for all 23 captured commands plus two project-local
LASAL extensions, 0x204A and 0x204B. These two extensions are not captured
commands. The five previously
blocked group commands 0x2049, 0x2085, 0x20A4, 0x2051 and 0x20E7 are active in
source. C# 46 tests, LASAL source-only/full-network static contracts and the WPF
VS2019 Debug build pass. The current LASAL source has NOT been rebuilt in the
LASAL IDE and has NOT been verified on a PLC.
CPU core/priority placement and packet recapture are also pending. The untracked
_Edit variant is not canonical. See API_DEVELOPMENT_BACKLOG_2026-07-10.md.

All numeric motion fields below are signed 32-bit little-endian LASAL internal DINT.
The API writes caller-provided DINT values directly to the packet.
Caller code must multiply the physical value by the selected LMC_Units constant,
round/check the DINT range, and pass the converted int to the motion API.
Read APIs return raw LASAL DINT; caller code divides by the same UNIT for display.
Current saved _LMCAxis1..9 profile (confirmed in Motion_Network):
  IntUnits      1 mm; UNIT MM = 10000
  VMax          75 mm
  AMax          7500 mm
  MoveType      _JERK_PROFILE
  JMax          75000 mm
  position      value * MM       (10000)
  velocity      value * MM       (10000), because MoveAbsolute expects app units/s
  acceleration  value * MM       (10000)
  deceleration  value * MM       (10000)
  jerk          (physical axis-unit/s^3 / 1000) * MM
RPM is not the MoveAbsolute velocity UNIT unless the PLC method explicitly
declares an RPM input. unit.h has no dedicated jerk UNIT; use the selected axis
application-unit constant after applying the _LMCAxis /1000 definition. Nonzero
Jerk affects _JERK_PROFILE only. Verify the downloaded PLC MoveType/JMax before
live motion.
Current saved _LMCRobotBase1 group profile:
  MoveType      _JERK_PROFILE
  JMax          50000 mm
Nonzero group Jerk is ignored unless the robot profile is _JERK_PROFILE. Verify
the downloaded robot MoveType/JMax before GroupStop or MoveLinear testing.
See UNIT_CONVERSION_MANUAL_2026-07-10.md.
Header: CommandId UINT[0], Reserved UINT[2], PayloadLength UINT[4], Reference UINT[6]

Target lookup/dispatch:
- 0x103C/0x1042 carry the caller-provided ASCII object name.
- LASAL compares it with actual names read from connected objects.
- The returned UINT16 is an opaque descriptor, not a pointer.
- Current deployment: single-axis descriptors 1..9, group 0x0100; 0 is invalid.
  Cartesian group identity/motion remains limited to axes 1..4 (X/Y/Z/U).
- GroupReadStatus carries the group descriptor in both header [6] and payload [8].

0x209F MoveAbsoluteEx, payload 32 bytes
[8] Position
[12] Velocity
[16] Acceleration
[20] Deceleration
[24] Jerk
[28] Direction
[32] BufferMode
[36] Execute
Current LASAL contract: Direction must be Shortest (2).

0x20A0 MoveRelativeEx, payload 32 bytes
Same layout as 0x209F. [8] is relative distance.
Direction must be Shortest (2); the signed distance selects relative direction.

0x20A2 MoveVelocityEx, payload 24 bytes
[8] Velocity
[12] Acceleration
[16] Deceleration
[20] Jerk
[24] Direction
[28] Execute
Deceleration must be 0 because `_LMCAxis.MoveEndless` has no deceleration input.
Direction must be Positive (1) or Negative (3). The C# serializer normalizes
the velocity sign and LASAL rejects a sign/direction mismatch.

0x20A4 MoveLinearAbsoluteEx, payload 96 bytes
[8..71] Position[0..15], 4 bytes each
[72] Velocity
[76] Acceleration
[80] Deceleration
[84] Jerk
[88] LASAL CoordSystem index
[92] TransitionMode
[96] BufferMode
[100] Execute
Current four-axis LASAL restrictions:
- Position[0..3] are X/Y/Z/U in the statically connected axis order.
- Position[4..15] must be zero.
- Velocity, acceleration and deceleration must be positive; jerk must be >= 0.
- CoordSystem must be None (0).
- TransitionMode must be ExactStop (0) or ContinuousDirect (2).
- BufferMode must be Aborting (1) or Buffered (2).
- Execute must be 1.
- Aborting maps to CmdConfig.MoveImmediately (bit 5, value 16); Buffered maps
  to CmdConfig 0. The LASAL call is LMCRobot.MoveLinearCoord.

0x2051 GroupReadActualPosition, payload 8 bytes
[8] CoordinateSystem DINT: None=0, ACS=1, MCS=2, PCS=3
[12] Enable BYTE = 1
[13..15] Padding = 0
The public enum is validated as None/ACS/MCS/PCS. This project has no dynamic
CalcModel, so all four values currently use GetRobotPosition with
CoordSystem:=0. Do not interpret the accepted MCS/PCS enum as a dynamic
kinematic conversion. The current tracked handler copies the complete 36-byte
_LMCPROF_POS (Pos1..Pos9) into response slots 1..9 and leaves slots 10..16 zero.
This differs from the older documented four-axis-only read contract. PLC
recapture must decide whether the public contract remains 1..9 readback or the
handler must explicitly zero slots 5..16. Group Move/SetKin/Lock remains limited
to axes 1..4 regardless of this readback issue.

LASAL-DINT v1 success response payload is exactly 68 bytes:
[8..71] Position DINT[16]
[72] FunctionStatus UINT16
[74] ErrorId INT16
A 4-byte command-error envelope is preserved as an unsuccessful typed result.
The captured PMAS 136-byte LREAL response is legacy and the PC parser rejects it.

0x20E7 SetKinTransformCartesian4Axis, payload 1320 bytes
[8..647] MC_KIN_NODE_DEF[16], 40 bytes each
  node+0  BackwardRatio LREAL
  node+8  ForwardRatio LREAL
  node+16 BackwardShift LREAL
  node+24 TransformFunction DINT
  node+28 AxisReference UDINT
  node+32 AxisType DINT
  node+36 Padding DINT
[648] iNumAxes DINT = 4
[652..1311] MC_KIN_REF aligned union remainder
[1312] eKinType DINT = 0 (Cartesian)
[1316] BufferMode DINT = 2 (Buffered)
[1320] Execute BYTE = 1
[1321..1327] ABI tail padding = 0
Public support is restricted to four identity-shift nodes X/Y/Z/U using unique
axis references from the same LMCConnection. Generic node counts, coefficients,
axis types and buffer modes are not capture-verified. The canonical LASAL source
uses a 2048-byte receive accumulator, 1328-byte request buffer and 1320-byte
queue payload, so the exact command fits without a second staging path. The
handler validates the entire captured identity shape, confirms axis clients
1..4, and configures the static identity mapping only. It does not call
LockProfile and does not create or modify a dynamic CalcModel. Profile locking
is the separate 0x2047 command.
The captured response payload is exactly 4 bytes (`UINT16 status + INT16
error`). The public method rejects the generic 8-byte acknowledgement shape.

0x2022 Stop, payload 16 bytes
[8] Deceleration
[12] Jerk
[16] BufferMode
[20] Execute

0x2085 GroupStop, payload 16 bytes
Same layout as Stop.
Current LASAL validation requires BufferMode=Aborting (1), Execute=1,
Deceleration>=0, Jerk>=0 and Deceleration>0 when Jerk>0. The handler calls
LMCRobot.StopMove(Mode:=3, Decel, Jerk).
The success ACK means the stop command was accepted, not that standstill has
already been reached. Poll GroupReadStatus afterward.

0x2049 GroupReset, payload 1 byte
[8] Execute BYTE = 1
The handler validates group reference 0x0100 and calls
LMCRobot.AxQuitError(AxisNo:=0).
This resets connected axis/hardware errors; it is not a guaranteed reset of the
robot profile error. Poll GroupReadStatus and inspect GroupErrorId afterward.

0x204A GroupPowerOn, payload 1 byte (project-local LASAL extension; not captured)
[8] Execute BYTE = 1
The handler starts asynchronous LMCRobot.RobotOn processing. A success ACK means
the request was accepted, not that every member axis is servo-ready. Poll
GroupReadStatus until local state bit 0x00040000 (IsPowerOn) is set.

0x204B GroupPowerOff, payload 1 byte (project-local LASAL extension; not captured)
[8] Execute BYTE = 1
The handler starts asynchronous LMCRobot.RobotOff processing. A success ACK means
the request was accepted, not that every member axis is powered off. Poll
GroupReadStatus until local state bit 0x00040000 (IsPowerOn) is cleared.

0x2047 GroupEnable / ProfileLock, payload 1 byte
[8] Execute BYTE = 1
The handler calls LMCRobot.LockProfile for the validated static mapping. A success
ACK means the lock request was accepted. The standard Maestro
NC_GROUP_STANDBY_MASK (0x00020000) identifies standby; this adapter sets it for
the locked standby condition exposed as IsStandby/IsEnabled.

0x2048 GroupDisable / ProfileUnlock, payload 1 byte
[8] Execute BYTE = 1
The handler requires ProfileInPosition(_LMCPROF_ProfileFinished), then calls
LMCRobot.UnlockProfile. A moving or unverified profile is rejected with -6.
The standard Maestro
NC_GROUP_DISABLED_MASK (0x00010000) identifies disabled; this adapter sets it for
the unlocked disabled condition exposed as IsDisabled.

Normal group order:
GroupPowerOn -> GroupReadStatus IsPowerOn -> SetKinTransform -> GroupEnable/lock
-> motion -> GroupStop/in-position -> GroupDisable/unlock -> GroupPowerOff ->
GroupReadStatus IsPowerOn=false.

Response payloads implemented by command-specific parsers:
- AxisInfo: 8 bytes, handle/reserved[0], status UINT16[4], error INT16[6]
- Axis ReadStatus: 12 bytes, state UDINT[0], status UINT16[4], error INT16[6],
  axis error UINT16[8], status word UINT16[10]
  The canonical LASAL server writes the native _LMCAXIS_STATUS bitfield to
  state[0]. PowerOn is bit 0 (0x00000001) and Standstill is bit 25
  (0x02000000). Do not apply the legacy PMAS 0x80/0x200 readiness masks.
  StatusWord[10] is reserved and currently always 0; DS402 StatusWord is not
  connected to this response yet.
- Axis ReadActualPosition: 8 bytes, position DINT[0], status UINT16[4],
  error INT16[6]
- Group ReadStatus: 12 bytes, state UDINT[0], status UINT16[4], error INT16[6],
  group error UINT16[8], padding UINT16[10]
  0x00040000 is the project-local LASAL Power Ready extension (IsPowerOn).
  0x00020000 is the standard Maestro NC_GROUP_STANDBY_MASK and 0x00010000 is
  NC_GROUP_DISABLED_MASK. The project-local part is the adapter condition that
  maps locked standby to IsStandby/IsEnabled and unlocked disabled to IsDisabled.
- GetGroupMembersInfo: exactly 1350 bytes; see RESPONSE_MODEL_DESIGN_2026-07-09.md
- Group ReadActualPosition: exactly 68 bytes, position DINT[16] at [0..63],
  status UINT16[64], error INT16[66]. The current source copies Pos1..Pos9 and
  zero-fills slots 10..16; the intended 4-vs-9 public read contract is pending
  PLC verification. Legacy 136-byte LREAL is rejected.

Callback and ownership:
- UDP callback payload remains raw because no event datagram capture/contract exists.
- Callback source-address validation and defensive payload copies are PC safeguards;
  they do not define a typed callback protocol.
- Multi-PC read sharing and motion/control ownership must be enforced by the LASAL
  session/dispatcher. Separate PC LMCConnection instances cannot enforce server ownership.

MoveCircle scope:
- The current public C# API has no MoveCircle method.
- No approved LASAL-DINT command ID, payload or response contract exists for it.
- It is not part of the 23 capture-backed commands or the two project-local
  power extensions and must not be inferred from
  the vendor LMCRobot.MoveCircleCoord method alone.
