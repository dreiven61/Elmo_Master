LMC DINT packet map
Status 2026-07-10: contract proposal, not a deployed/verified PLC implementation.
The tracked TCPMotionInterface and the untracked _Edit variant do not implement
this map end-to-end. Do not use the current WPF app for live motion until the
P0 items in API_DEVELOPMENT_BACKLOG_2026-07-10.md are complete.

All numeric motion fields below are signed 32-bit little-endian LASAL internal DINT.
The API writes caller-provided DINT values directly to the packet.
Caller code must multiply the physical value by the selected LMC_Units constant,
round/check the DINT range, and pass the converted int to the motion API.
Read APIs return raw LASAL DINT; caller code divides by the same UNIT for display.
Current Elmo a01-a04 profile (confirmed in Motion_Network):
  position      value * DEG      (10000)
  velocity      value * DEG      (10000), because MoveAbsolute expects app units/s
  acceleration  value * DEG      (10000)
  deceleration  value * DEG      (10000)
  jerk          use 0 until the nonzero physical conversion is approved
RPM is not the MoveAbsolute velocity UNIT unless the PLC method explicitly
declares an RPM input. unit.h has no dedicated jerk UNIT, while _LMCAxis defines
jerk as application units/sec^3/1000.
See UNIT_CONVERSION_MANUAL_2026-07-10.md.
Header: CommandId UINT[0], Reserved UINT[2], PayloadLength UINT[4], Reference UINT[6]

0x209F MoveAbsoluteEx, payload 32 bytes
[8] Position
[12] Velocity
[16] Acceleration
[20] Deceleration
[24] Jerk
[28] Direction
[32] BufferMode
[36] Execute

0x20A0 MoveRelativeEx, payload 32 bytes
Same layout as 0x209F. [8] is relative distance.

0x20A2 MoveVelocityEx, payload 24 bytes
[8] Velocity
[12] Acceleration
[16] Deceleration
[20] Jerk
[24] Direction
[28] Execute

0x20A4 MoveLinearAbsoluteEx, payload 96 bytes
[8..71] Position[0..15], 4 bytes each
[72] Velocity
[76] Acceleration
[80] Deceleration
[84] Jerk
[88] LASAL CoordSystem index
[92] TransitionMode
[96] BufferMode
[100] Execute

0x2022 Stop, payload 16 bytes
[8] Deceleration
[12] Jerk
[16] BufferMode
[20] Execute

0x2085 GroupStop, payload 16 bytes
Same layout as Stop.

LASAL 0x209F parser replacement:

_StdLib.MemCpy(dest:=#pos, source:=#ReceiveBuf[8], size:=4);
_StdLib.MemCpy(dest:=#velo, source:=#ReceiveBuf[12], size:=4);
_StdLib.MemCpy(dest:=#acc, source:=#ReceiveBuf[16], size:=4);
_StdLib.MemCpy(dest:=#dec, source:=#ReceiveBuf[20], size:=4);
_StdLib.MemCpy(dest:=#jer, source:=#ReceiveBuf[24], size:=4);
_StdLib.MemCpy(dest:=#dir, source:=#ReceiveBuf[28], size:=4);
_StdLib.MemCpy(dest:=#bufMode, source:=#ReceiveBuf[32], size:=4);
_StdLib.MemCpy(dest:=#Exec, source:=#ReceiveBuf[36], size:=4);

LMCAxis.MoveAbsolute(
  Position:=pos,
  Speed:=velo,
  Accel:=acc,
  Decel:=dec,
  Jerk:=jer
);

LASAL 0x20A4 parser replacement:

Change the class variable GroupExecute from BYTE to DINT.
The C# request carries 16 DINT positions (64 bytes), while the current
GroupMovePos copy example below copies only 36 bytes (9 positions). The
canonical LASAL robot/group axis count must be fixed before implementation.

_StdLib.MemCpy(dest:=#GroupMovePos, source:=#ReceiveBuf[8], size:=36);
_StdLib.MemCpy(dest:=#GroupVelocity, source:=#ReceiveBuf[72], size:=4);
_StdLib.MemCpy(dest:=#GroupAccel, source:=#ReceiveBuf[76], size:=4);
_StdLib.MemCpy(dest:=#GroupDecel, source:=#ReceiveBuf[80], size:=4);
_StdLib.MemCpy(dest:=#GroupJerk, source:=#ReceiveBuf[84], size:=4);
_StdLib.MemCpy(dest:=#GroupCoordSystem, source:=#ReceiveBuf[88], size:=4);
_StdLib.MemCpy(dest:=#GroupTransitionModeInput, source:=#ReceiveBuf[92], size:=4);
_StdLib.MemCpy(dest:=#bufMode, source:=#ReceiveBuf[96], size:=4);
_StdLib.MemCpy(dest:=#GroupExecute, source:=#ReceiveBuf[100], size:=4);

No LREAL-to-DINT conversion is required in the PLC.
